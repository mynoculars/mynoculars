| **D-35** *(Phase 3)* | Langfuse observability is isolated in one package, `research_agent/langfuse/`: `client.py` is the ONLY file that imports the `langfuse` SDK (`build_client()` returns a real client or `None`, never raises); every other business module (`cli.py`, `orchestration/graph.py`, `llm/router.py`, `llm/client.py`, `retrieval/hybrid.py`, `memory/semantic_memory.py`, `agents/gathering.py`, `agents/compilation.py`) imports only the thin public functions in `langfuse/__init__.py` (`start_trace`, `span`, `generation`, `event`, `score`, `end_trace`, `flush`, `shutdown`) and never sees an SDK object, a trace handle, or a span handle. Off by default (`LANGFUSE_ENABLED=false`): zero SDK import, zero network calls. A single generic `traced_node()` wrapper applied at `graph.py`'s 13 `add_node(...)` call sites spans every node without touching any node function body. The installed SDK is v4.x (OTel-based, no stateful `.trace()` object) — session/environment grouping goes through `propagate_attributes(...)`, verified live to survive both being read outside its lexical `with` block and LangGraph's own `contextvars`-based parallel dispatch. Nesting: `TraceContext` also accepts an optional `parent_span_id`, and the run's open root span was already tracked in `Observer._roots` for `end_trace`'s sake, so real OTel parentage needed no new state and no call-site changes; `_trace_context()` additionally yields to an already-current span of the same trace, so observations made inside a `span_ctx()` block nest under that block rather than under the root. (Earlier revisions of this row recorded flat traces as a deliberately deferred limitation — that is no longer accurate.) `Observer.span_ctx()` wraps the SDK's `start_as_current_observation` so a node span opens BEFORE the node runs and its timestamps are real; the post-hoc `span()` is kept for callers with no block to wrap, and carries `duration_ms` as metadata because a span created after the work finished would get a negative duration from a true end time. `api/server.py` opens and closes a root trace per REQUEST — not per run — because `propagate_attributes` is sync-only and attaches to the calling thread, and FastAPI serves these `def` endpoints from a reused threadpool; entering on one request and exiting on another would leak a session id onto the next request that worker handles. `create_score` takes `trace_id` ONLY: the ingestion API accepts exactly one score target and rejects `traceId`+`sessionId` together with HTTP 400, so scores inherit their session from the trace they attach to. | `langfuse/client.py`, `langfuse/observer.py`, `langfuse/helpers.py`, `langfuse/pricing.py`, `langfuse/__init__.py` |

| **D-38** | **Retrieval is a LADDER, not a single tier.** `tools/retrieval_chain.py` tries corpus -> ONE reformulated corpus retry -> MCP -> the answering model's own knowledge (`tools/model_knowledge.py`), stopping at the first tier returning evidence above `min_evidence_score` (the same predicate D-17 uses for coverage, passed in so the two can never drift). Rationale: before this the system had exactly one tier, and a corpus that did not contain the subject produced "the retrieved evidence does not cover it" -- reporting a RETRIEVAL limitation as an absence of knowledge, which is the wrong answer to give. Honesty invariants, all enforced: model-sourced items always carry `source="model"` and are never relabelled; `compile_report`'s old GROUNDING RULE (which forbade model knowledge outright, and was therefore the direct cause of the failure) is replaced by an ATTRIBUTION RULE requiring model-derived claims to be marked as general knowledge in the prose; `critique` is told not to fail a report for using attributed model knowledge; telemetry reports `corpus_recall` and `model_sourced_items` alongside `recall`, so "we answered it" and "the corpus answered it" can never be confused. The model tier is LAST, so a real document always wins. Off by one flag (`MODEL_KNOWLEDGE_ENABLED=false`) restores the exact pre-D-38 posture, escalation included. | `tools/retrieval_chain.py`, `tools/model_knowledge.py`, `prompts/templates.py`, `assembly.py`, `config.py` |
| **D-39** | **A tier "answered" only if its evidence is on TOPIC, not merely high-scoring.** `retrieval_chain._sufficient` now requires one shared distinctive term (4+ chars, minus query scaffolding) between the query and a hit that cleared `min_evidence_score`. Rationale: RRF score is an ORDINAL signal -- "best of what came back" -- and a fixed-k search over a small corpus always returns k documents, so there is no empty state and a score test alone can never fail. Live (run p205.90-check): asked for GDP per capita and demographics against a ten-document Redis corpus, both legs returned the same irrelevant documents, cross-leg agreement pushed them to ~1.0, tier 1 declared success, the model tier was never reached, and the report said the evidence did not cover it -- the exact give-up D-38 exists to remove, re-entering through the sufficiency test. One shared term is deliberately a floor against wholly off-topic matches, not a relevance ranker. | `tools/retrieval_chain.py` |
| **D-40** | **Citations are goal ids, never pasted evidence text and never internal scores.** `compile_report` specifies `[g1]` / `[g1][g3]` exactly, and forbids three things live output actually did: running the source sentence into the claim with no delimiter ("...whole blobRedis is an in-memory data store..."), printing internal bookkeeping (`[g1 \| model \| score=0.60]`) into user-facing prose, and inventing citation text for claims no evidence item supports (run p205.93-check attributed Cassandra and DynamoDB descriptions to a corpus containing neither). | `prompts/templates.py` |
| **D-41** | **The model tier gets hard anti-fabrication limits, because self-reported confidence does not catch confabulation.** `templates.model_knowledge` forbids inventing names of operations/exercises/programmes, tells the model to prefer stable facts over date-pinned ones, and requires confidence to reflect the WEAKEST part of a compound claim. | **D-42** | **Model recollection never enters durable memory, and recalled memory may never re-frame a query.** `SemanticMemory.store_run` filters out `source="model"` as well as `source="memory"`; `templates.compose_goals` labels recalled facts as background from UNRELATED runs and forbids them narrowing the question. Rationale, from runs p205.96/.97-check: the army run wrote 28 memory items of which 24 were model recollection, and the next, unrelated run ("Compare India and US" — an open question that had previously produced economic and demographic goals) recalled five of them and composed an entirely MILITARY goal set, inheriting PLA-doctrine prose verbatim into an India-vs-US report. Two independent reasons the write must not happen: storing recollection caches a lookup that was never expensive, and it launders an unverified guess into something a later run reads back tagged `source="memory"`, indistinguishable from document-backed evidence, before any retrieval has run. | **D-43** | **Citation correctness is enforced deterministically where it can be, and asked of the critic where it cannot.** `compilation._clean_citations` strips any verbatim run of an evidence item's own content from the prose (run p205.95-check pasted source sentences into claims) and drops `[gN]` markers naming goals that retrieved nothing, counting both into telemetry as `citations_pasted_evidence_removed` / `citations_to_unevidenced_goals`.
